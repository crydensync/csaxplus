Why

Auth you run, not auth you rent.

Every project ends up rewriting auth from scratch, or handing user data to a third-party provider. CrydenSync is a library, not a service.

Own your users

No hosted service, no data leaving your infrastructure. Users, sessions and audit logs stay in your own database, under your own control.

No vendor lock-in

Plain Postgres tables, or one SQLite file. No proprietary format, no export migration, nobody's egress bill.

Zero telemetry

The engine never phones home. Logs and audit events go wherever you wire them — never to us.

Nothing in this repo runs on its own initiative: breach checking, IP geolocation, log shipping and webhook delivery all ship as interfaces with zero implementations. Bring your own, or leave them off and nothing else changes.

Auth

The whole auth surface, not a login form.

Every capability below is a first-class part of the engine — not a plugin, not an add-on module, not a per-seat upgrade.

Passwords & sessions

Signup, login, and logout on a single device or all of them. JWT access tokens with rotating opaque refresh tokens and theft/reuse detection.

Six OAuth providers

Google, GitHub, Microsoft, Discord, GitLab and Apple. An email collision returns a conflict rather than silently linking — auto-linking on email match alone is an account-takeover vector.

Two-factor, unified

TOTP and passkeys (WebAuthn) under one pause state. An account can have either, both, or neither, and Login reports whichever are enrolled.

Magic links

Passwordless login for existing accounts. The link proves email ownership — the primary factor — so it routes through the same second-factor gate a password does.

Recovery codes

A fallback for an account that already has a real second factor. If that factor is removed while codes remain, they stop being offered rather than becoming a standing backdoor.

Email verification & change

Token issue and confirm as engine primitives. Delivery is pluggable — the engine hands you a raw token and never assumes your domain or routes.

Password policy

Secure-by-default NIST 800-63B rules. A violation returns every broken rule at once, as stable codes, so a client can show them together.

Extensible JWT claims

Attach roles, tenant IDs, plan — whatever your authorization layer needs — to every access token. The seven registered claim names are refused all-or-nothing.

API keys

ck_-prefixed machine credentials for CI and cron, deliberately outside the second-factor system. Only the hash is stored, and every read failure looks identical.

Security

Signals, not surprise lockouts.

Detection here records what looks wrong and lets a human decide. No login is ever blocked, delayed or challenged by an anomaly — and none of it returns an error a client could branch on.

Anomaly detection

Six signal codes over login attempts: new IP, new device, per-user and per-IP failure velocity, refresh-token reuse, and an unusual count of concurrent sessions. Report-only, always.

Credential-stuffing detection

One IP spraying one leaked password across many accounts — the attack per-account lockout structurally cannot see, because each account only ever witnesses a single failure.

Lockout that survives a restart

Persistent and database-backed, so it holds through restarts and stays correct across multiple running instances. Five attempts, fifteen minutes, both configurable.

Rate limiting, two layers

Per-user windows on login, signup and magic-link, plus a coarser per-IP edge guard. In-memory for a single instance; point it at Redis and every replica counts against one shared window.

bcrypt or Argon2id

Two real implementations of one interface. Every hash names its own algorithm, so a table can hold both mid-migration — and out-of-date hashes upgrade themselves on the next successful login.

Named sessions

Chrome on macOS instead of a UUID, computed on read from the IP and User-Agent every session already stores. No migration, no new column.

AI admin

Four assistants. None of them can act.

All four read the engine's own audit history and current settings. There is no code path in any of them that locks an account, changes a config value, or takes any action at all.

Weekly digest

A plain-English summary of the week. A quiet week renders as two lines.

Support assistant

"Why can't user X log in" — answered from lock state, recent failures and session state, never guessed at.

Config advisor

Reads 30 days of history against the settings actually in force and suggests changes. A suggestion pre-fills a field; a human still saves it.

Ask-AI widget

The one piece your own end users can embed, answering questions about their own account.

A prompt injection can change what query the model tries. It cannot change what the code lets that query read.

The widget discards whatever identity filter the model produced and substitutes the id verified from the caller's own token — unconditionally, rather than validating and rejecting. Every phrasing of a question, honest or adversarial, produces the exact same scoped query, so there is no error oracle to learn from either.

Backends

Postgres, or a single file.

Two real backends behind one set of interfaces — not a production path and a toy. Exactly one environment variable chooses between them, and setting both is a startup error rather than a silent preference.

Postgres

everything

Postgres 13+ — local, Docker, or hosted (Supabase, Neon, RDS).

  • The complete auth surface
  • The full admin console — users, metadata, webhooks, logs, digest
  • Support diagnosis, config tuning, anomaly review
  • AI provider settings, encrypted at rest

SQLite

core auth only

One writable path and a volume. No database server to run at all.

  • Signup, login, refresh, sessions, password change
  • Email change, OAuth, TOTP, passkeys, recovery codes
  • Magic links and API keys
  • Everything under /v1/admin answers 501 — the console's tables are Postgres-only

Migrations are compiled into the binary and applied on boot, so a git pull or a new container image brings its own schema change with it. Teams who would rather review schema changes set SKIP_AUTO_MIGRATE and run api migrate in the pipeline instead.

Writes on the admin surface are few and deliberate: operator metadata (which becomes JWT claims), a review note on a flagged event, and a settings save. Nothing else. No AI feature can reach any of them — no tool holds a reference, and the engine's interfaces carry no method that could call one.
